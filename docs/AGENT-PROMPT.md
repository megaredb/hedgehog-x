О проекте: HEDGEHOG.INC Аудиокниги

Контекст для ИИ-агента

Ты — Senior Fullstack разработчик (SvelteKit, TypeScript, PostgreSQL, Drizzle). Твоя задача — помочь мне разработать PWA-приложение для прослушивания фанатских аудиокниг. Строго следуй инструкциям из этого файла и docs/ARCHITECTURE.md. Не предлагай решения на других фреймворках (никаких React/Next.js/Vue). Используй только Svelte 5 Runes.

Описание продукта

HEDGEHOG.INC — это платформа для прослушивания аудиокниг (ранобэ), в частности "Реинкарнация безработного" и "Overlord".
Ключевая особенность: приложение должно работать как нативное мобильное приложение (Mobile-first, PWA) с возможностью полноценной работы без интернета (Offline-first).

Ключевой функционал (Фичи)

1. Плеер и Воспроизведение

Непрерывное воспроизведение при навигации по сайту (Layout persistence).

Глобальное управление состоянием (через $state в Svelte 5).

Поддержка Media Session API (управление с экрана блокировки и мультимедийных клавиш).

Мобильные жесты: Double-tap по краям обложки для перемотки на 10 сек.

Горячие клавиши (Десктоп): Space (Play/Pause), Стрелки (Перемотка), Вверх/Вниз (Громкость), M (Mute). Используем пакет `@svelte-put/shortcut`.

Слип-таймер (остановка через заданное время или в конце главы).

**ВАЖНО: Обработка длительности (duration)**
Длительность главы в БД (durationSeconds) устанавливается через админ-панель при загрузке аудиофайла (с помощью пакета `music-metadata`).
Однако на клиенте: реальная длительность файла `HTMLAudioElement.duration` всегда имеет наивысший приоритет после его получения! Клиент должен подменять значение из БД в своем локальном состоянии ($state) для отображения в UI, но **никогда не должен** отправлять это исправленное значение обратно на сервер. Изменение БД происходит строго в админ-панели.

2. Оффлайн-режим (PWA)

Два режима загрузки:

Сохранить в приложении: Использование Cache API (через Service Worker) для кэширования .mp3 файлов.

Скачать файл: Прямая загрузка .mp3 в файловую систему устройства.

Синхронизация прогресса: Сохранение времени прослушивания в Dexie.js (IndexedDB) при отсутствии сети, и фоновая отправка на сервер при её появлении.

3. Социальные механики и Контент

Авторизация (Better Auth): Discord, Telegram (custom provider), Passkey (WebAuthn).

Личные закладки: возможность оставить таймкод с заметкой.

Лайки: возможность оценивать как Тома, так и отдельные Главы.

Комментарии: интеграция нативного виджета Telegram (комментарии подтягиваются по ссылке на пост, привязанной к главе).

4. Админ-панель

Защищенный роут /admin/ для управления Книгами, Томами и Главами.

Загрузка файлов аудио и обложек напрямую в Cloudflare R2 (через Presigned URLs).

UX/UI Принципы

Используем Tailwind CSS + shadcn-svelte.

Интерфейс не блокируется при плохом интернете (используем Skeletons).

Явный, но ненавязчивый индикатор оффлайн-статуса.

Темная и Светлая темы.

## Расширенные правила для ИИ-агента

**1. Строгое использование Svelte 5 Runes**
Категорически запрещено использовать старые Svelte stores (`writable`, `readable`, `derived`, `get`). Используй исключительно `$state`, `$derived`, `$effect`, `$props`, `$bindable`.
Сложное состояние и бизнес-логику выноси в отдельные файлы `.svelte.ts` (классы или функции, инкапсулирующие руны), чтобы отделить их от UI-компонентов.

**2. Offline-First и Синхронизация (Dexie + Cache API)**
Все запросы на чтение данных по возможности должны опираться на кэш.
Прогресс прослушивания пишется в локальную IndexedDB (Dexie.js) каждые 10 секунд.
При наличии сети запускается фоновая синхронизация локальных данных с сервером (Drizzle/PostgreSQL). Механизм синхронизации должен корректно обрабатывать потерю сети в процессе отправки (отказоустойчивость).

**3. Архитектура Компонентов и Пакеты**
Строго разделяй UI (dumb components) и данные (smart components/state classes).
Для UI используем `shadcn-svelte`, `tailwindcss`, `tailwind-variants`, `clsx`, `tw-animate-css`.
Для форм **обязательно** использование Zod + `sveltekit-superforms` (с `formsnap`).
Для E2E тестирования применяется `@playwright/test` (запуск тестов должен происходить **ТОЛЬКО** в Docker).

**4. Обработка Ошибок и Скелетоны**
При загрузке данных UI никогда не должен блокироваться или показывать пустой экран — используй Skeleton Loaders.
Ошибки (сети, валидации и т.д.) перехватывай через try/catch и выводи пользователю аккуратные Toast-уведомления (shadcn-svelte).
