> Набор документов для людей и ИИ-агентов, которые продолжают работу над проектом
> без доступа к истории предыдущих сессий.
>
> **Снимок:** 2026-11-18, ветка `dev`, коммит `5f67c5d` (worktree
> `.agents/worktrees/dsh-d6a6b302-2f83`). После изменений кода сверяйся с кодом.

## Быстрый старт для новой сессии

1. Прочитай `AGENTS.md` (правила, команды, ловушки).
2. Открой `docs/PROJECT_MAP.md` и найди нужный маршрут/файл/таблицу.
3. Для понимания потоков — `docs/ARCHITECTURE.md`.
4. Перед правками в проблемных зонах — `docs/AUDIT.md` (P0/P1).
5. Для запуска/деплоя — `docs/OPERATIONS.md`.

## Как читать документы

- **Источник истины — код.** Документы описывают состояние на снимок и явно помечают
  предположения. Если видишь расхождение — проверь файл и обнови документ.
- **Ссылки на код** даны путями от корня репозитория. В GitHub/IDE они кликабельны.
- **Severity** в AUDIT: `P0` — потеря данных/деплой сломан; `P1` — безопасность,
  заметная функциональность, CI; `P2` — средние баги/ops/UX; `P3` — полировка/мёртвый код.
- **«Проверено»** означает, что факт воспроизведён командой/запросом, а не только
  вычитан из кода. Команды и результаты — в AUDIT §2.

## Правила поддержания

- Обновляй этот индекс при добавлении нового документа.
- Не дублируй длинные разделы между файлами: `AGENTS.md` ссылается, `docs/*` содержит детали.
- `GEMINI.md` — короткий указатель на `AGENTS.md`, чтобы не было двух расходящихся
  версий инструкций.
- Все даты в документах — в формате ISO (`YYYY-MM-DD`); времена — с таймзоной.
