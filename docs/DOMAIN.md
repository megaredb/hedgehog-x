## 2. Иерархия и идентификаторы

```
Book 1 ── N Volume 1 ── N Chapter
                 └──── N Illustration
```

- `books.id`: строка до 128 символов; в сиде — slug (`overlord`, `mushoku_tensei`),
  в админке — slug из названия или случайные 8 символов.
- `volumes.id`: до 128; в сиде — `{bookId}_vol_{n}`; в админке — `{bookId}_vol_{n}_{slug|random}`.
- `chapters.id`: до 128; в сиде — `{volumeId}_c{n}`; в админке — `{volumeId}_ch_{n}_{random}`.
  **ID главы используется как имя файла в OPFS** — не меняй формат без миграции скачанных файлов.
- `illustrations.id`: до 128; в админке — `ill_{volumeId}_{random}`.
- `bookmarks.id`: UUID (36 символов).
- `user.id`: для Telegram — числовой Telegram ID (строка), для Discord — ID better-auth.
- `listening_sessions.id`: UUID.
- `daily_listening_stats.id`: детерминированная строка
  `{date}_{bookId|nobook}_{chapterId|nochapter}_{userId|anon}` (до 128 символов, но может
  переполниться — см. AUDIT).

**Порядок** определяется полями `volumeNumber`, `chapterNumber`, `sortOrder`, а не ID.
Уникальность номеров в БД **не гарантирована** (нет unique-индексов).

## 3. Инварианты контента

1. Книга → тома → главы; удаление книги каскадно удаляет тома, главы, иллюстрации,
   прогресс/лайки/закладки, сессии и дневную статистику (FK cascade).
2. `chapters.audioUrl` и `durationSeconds` обязательны. Длительность — целое число секунд
   (может быть 0, если админ не заполнил).
3. `illustrations.sortOrder` — целое, по умолчанию 0; сортировка по возрастанию.
4. `status` книг/томов — свободный `varchar(50)`, UI понимает `ongoing` и `completed`
   (остальные значения отображаются как «Выходит»).
5. `telegramPostUrl` может быть полной ссылкой `https://t.me/channel/123` или
   `channel/123`; виджет комментариев парсит оба формата.
6. `themeColor` — 6 hex-символов без `#`; проверки в БД нет.
7. `coverUrl/imageUrl/audioUrl` — относительные (`/img/...`, `/audio/...`) или абсолютные
   URL; абсолютные URL известных CDN-хостов переписываются под выбранное зеркало.
   «Автоматически» выбирает RU-зеркало на RU-домене или основное зеркало; отключённые
   зеркала не предлагаются пользователю.

## 4. Инварианты пользовательских данных

1. Прогресс: один ряд на `(userId, chapterId)`; `progressSeconds >= 0`; сервер при upsert
   берёт `GREATEST(old, new)`, чтобы откат назад не терял прогресс.
2. Завершение: `isCompleted` не сбрасывается в false сервером, если уже true.
3. Лайк: один ряд на `(userId, volumeId|chapterId)`; повторный like — `ON CONFLICT DO NOTHING`.
   Счётчик лайков — агрегат по всем пользователям, отдаётся в `/api/books/[bookId]`.
4. Закладка: `timestampSeconds` — целое; `note` — до 500 символов; владелец — `userId`.
5. Гость: сервер не отдаёт его данные (`/api/user/sync` → 401), прогресс/закладки/
   лайки живут только в Dexie. При входе guest snapshot загружается через POST и
   только затем локальные данные получают owner; при смене аккаунта — очищаются.
   Аналитика гостя хранится с `userId = NULL`.
6. Сессия прослушивания: `listenedSeconds` — целое **1..300**; `startedAt` — дата;
   сервер проверяет существование главы и подставляет `bookId/volumeId`.
7. Дневная статистика: ключ включает дату в **UTC**; `sessionsCount` инкрементируется
   на 1 за каждый принятый пакет, `totalSeconds` — сумма.
8. `role` пользователя: `user` (по умолчанию), `admin` или `author`; проверять только на сервере. Автор — единственный, имеет админ-доступ и по умолчанию исключён из статистики.

## 5. Состояния (state machines)

### Загрузка главы (`downloads.status`)

```
queued ──> downloading ──> downloaded
   │            │
   └────────────┴──> error   (остаётся в БД; повторная постановка возможна)
```

- Очередь обрабатывается **последовательно** (один активный download).
- При отмене запись удаляется, OPFS-файл удаляется.
- При сетевой ошибке частичный OPFS-файл **не удаляется** (AUDIT P2) — возможен
  проигрыш обрезанного файла.

### Плеер

`idle → loading → playing ⇄ paused → ended`

- `isPlaying` — намерение играть; `isBuffering` — ждём данные; `isLoading` — грузим трек;
  `isError` + `errorMessage` — ошибка.
- `currentTime`, `duration`, `progress`, `bufferedTime` синхронизируются из `<audio>`.
- Завершение трека: сохранить прогресс как completed → repeat-one? → sleep-timer-end? →
  auto-advance/next или pause.

### Синхронизация

- **Optimistic UI**: сначала Dexie, потом `syncQueue`, потом отправка.
- Очередь — не универсальный журнал: consumer'ы есть у лайков, прогресса,
  listen-сессий и закладок (`bookmarkSync`). Каждый элемент хранит `ownerUserId`;
  flush отправляет только действия текущего владельца.
- Logout/истечение сессии очищают личные данные, очередь и `syncOwner`.
- Guest→аккаунт: новый аккаунт (`isNewUser`) импортирует автоматически; существующий —
  только после явного согласия. Отказ удаляет guest-данные.
- При конфликте сервер ↔ локально побеждает сервер (hydrate с purge), что может
  стирать несинхронизированные локальные изменения.

## 6. Бизнес-правила

- Лайки в UI доступны только авторизованным; гость видит модалку входа.
- Скачивание/прослушивание/закладки доступны гостю (локально).
- История и закладки — локальные списки; история не удаляется на сервере.
- Завершение тома: модалка открывается, когда **последняя глава тома** завершилась
  в текущей сессии; можно перейти к следующему тому.
- Комментарии — внешний Telegram-виджет; своя таблица комментариев отсутствует.
- Админка — `role=admin` или `role=author`; первый админ в production назначается вручную в БД
  (в dev есть кнопка «сделать меня админом»).
- Аудио раздаётся публично (без подписанных URL и DRM); ссылки на R2 прямые.
- Umami — опционально; собственные метрики прослушивания работают без него.
- Подписка — доступ к закрытому сообществу, **не** гейт контента: книги, главы и плеер остаются доступны без неё.
- Ручная выдача: 7 ₽ = 1 день; сумма переводится в дни как `floor(amount / 7)`, остаток не даёт дней.
- Ручное продление считается от `max(now, manual_expires_at)`; раннее продление не сгорает.
- `is_lifetime` перекрывает ручную дату; `blocked_at` и `revoked_at` перекрывают lifetime и источники.
- Отзыв (`revoked_at`) останавливает подписку, сохраняя остаток дней в `revoked_remaining_ms`; восстановление начинает остаток заново от текущего момента.
- Блокировка удаляет все сессии пользователя, запрещает создание новой и замораживает остаток ручных дней в `blocked_remaining_ms`; разблокировка возвращает остаток.
- После входа/регистрации источники подписки проверяются автоматически.
- Источники Boosty складываются: активен Telegram **или** Discord → доступ есть. Один неактивный источник не сбрасывает другой.
- Ошибка проверки источника (сеть, 401, бот не админ) не делает источник неактивным; сохраняется прежнее состояние и `last_error`.
- Каждое ручное изменение и переход источника пишутся в `subscription_events`.
- Пользователь может инициировать проверку статуса; администратор — выдачу/отзыв/блокировку и проверку.
- Boosty API/токены не используются: сигналы — членство в Telegram-группе и роль Discord.
- После первого изменения в админке цена дня хранится в `subscription_settings`, а не только в env.
- Смена цены `new`: старые донаты/выданные дни сохраняют старую цену. Смена `all`: оставшийся срок активных ручных подписок пересчитывается пропорционально, lifetime не меняется.
- При смене цены активные подписчики получают уведомление; его можно закрыть, а продление подписки закрывает его автоматически.
- Доход считается только по ручным донатам (`grant` + `amount_rub > 0`); Boosty-платежи не импортируются.

## 7. Термины, которых в проекте нет (важно не путать)

- **Нет** сущности «покупка», «платёж», «плейлист», «пользовательский плейлист»,
  «комментарий» в БД, «рейтинг», «просмотр». Подписка теперь есть (см. выше).
- **Нет** интеграции с Boosty API, хранения Boosty-токенов или автосписаний.
- **Нет** отдельного каталога всех книг и поиска (despite `strings.common.search`).
- **Нет** серверного API для закладок/прогресса по отдельности — всё через
  `POST /api/user/sync`.
- **Нет** серверной очереди транскодинга: аудио загружается как есть.
- **Нет** i18n: интерфейс русский, `strings` — не полноценная локализация.
